# FiberHome SR1041Y: AlphaWRT port

Status of AlphaWRT on the FiberHome SR1041Y, the Wi-Fi 6 router TM
supplies with Unifi in Malaysia, behind a separate fibre box (ONT). Everything listed as working was tested on a
real unit.

> **Early bring-up.** AlphaWRT installs to flash bank B and boots from it,
> with the stock firmware kept in bank A. The Internet comes in on port 1
> (WAN); PPPoE on a live Unifi line is not tested yet. The first install needs
> the UART.

## Hardware

| | |
|---|---|
| SoC | EcoNet/Airoha **EN7561DU** (chip marking); reports itself as the **EN7528** platform ("free bootbase" v1.1, `7528DRAMC`) |
| CPU | 2x MIPS 1004Kc, little-endian |
| RAM | 256 MiB DDR3 |
| Flash | Micron MT29F2G01 256 MiB SPI-NAND, 2048 + 64 OOB, 128 KiB blocks, EcoNet BMT |
| Switch | EN7528 internal GbE switch: port 1 = WAN, ports 2-4 = LAN |
| Wi-Fi | MediaTek **MT7915** DBDC (2.4 + 5 GHz, Wi-Fi 6), PCIe |
| Fibre | none: the SoC has an xPON MAC and the stock firmware carries EN7571 modules, but the board has no optics. It sits behind the ISP's fibre box (ONT) |
| Bootloader | EcoNet "free bootbase" v1.1 (not U-Boot) |
| UART | header **XP1**, 5 holes (square pad = 1): **2 = TX, 3 = RX, 4 = GND**, 115200 8N1, 3.3 V |
| hwcfg | `0x10001003` |

AlphaWRT target: `airoha/en7528`, device `fiberhome_sr1041y`.

## Flash layout (stock, kept as is)

| mtd | Name | Offset | Size | Content |
|---|---|---|---|---|
| 0 | `boot` | 0x0000000 | 2 MiB | free bootbase (LZMA at +0x20000) |
| 1 | `KernelA` | 0x0200000 | 40 MiB | bank A, UBI |
| 2 | `KernelB` | 0x2a00000 | 40 MiB | bank B, UBI |
| 3 | `config` | 0x5200000 | 35 MiB | UBI: `factory`, `userdata`, `reserved` |

Above 0x7500000 the flash holds only the BMT/BBT: a full dump of that region
was erased (all 0xFF). Bank format and boot flags: [BANK-FORMAT.md](BANK-FORMAT.md).

### Factory data

The MACs and the Wi-Fi calibration are not in raw flash. They are files in the
UBIFS volume `factory` on the `config` UBI:

| File | Content |
|---|---|
| `factory_conf` | uci-like `config key '<name>'` / `option value '<value>'`; MACs in `brmac` (LAN) and `internetmac` (WAN). The sticker MAC is `brmac - 1`. Also holds the unit's admin password and Wi-Fi key: never publish a copy |
| `wlan/RT30xxEEPROM_5.bin` | 32 KiB MT7915 EEPROM (starts `15 79`) |
| `pre_usrconfig_conf` | ISP defaults (see Unifi below) |

`config` is `read-only` in the DTS and has `compatible = "linux,ubi"`, so the
kernel attaches it read-only. Preinit (`09_mount_factory_data`) mounts the
`factory` volume of that UBI device read-only at `/tmp/factory`. Two traps:
it must run before `70_initramfs_test`, which ends `preinit_main` on RAM
boots, and it must name the device (`ubiN:factory`): `ubi:factory` only
searches `ubi0`, which is bank B once AlphaWRT boots from flash.

### Unifi defaults from the stock firmware

From `factory/pre_usrconfig_conf` of a TM unit; they match AlphaWRT's
`isp.json` Unifi preset:

| Service | VLAN | Stock type |
|---|---|---|
| Internet | 500 | PPPoE routed, NAT, IPv4 + IPv6 (PD) |
| IPTV | 600 | bridged |
| Voice | 400 | bridged |
| TR-069 | 209 | routed |

AlphaWRT's Unifi preset fills in PPPoE on VLAN 500 on the WAN port.

## Changes to the tree

Device support (`add_sr1041y.py` applies them, idempotent):

- `dts/en7528_fiberhome_sr1041y.dts`: 256 MiB RAM, stock partitions, `config`
  as read-only `linux,ubi`, `KernelB` as `linux,ubi` (AlphaWRT's bank), GbE
  PHYs enabled (the dtsi disables them), MT7915 on `pcie1` with
  `mediatek,eeprom-name`, `pcie0` left disabled, `&uart1` clock 7.3728 MHz.
- `en7528/base-files/lib/upgrade/platform.sh`: `sysupgrade` into bank B
  (`CI_UBIPART=KernelB`, kernel volume `ubi_kernel` created static with ID 0,
  which is what the bootbase loads).
- `en7528/base-files/usr/sbin/alphawrt-bootbank`: bank switching with the
  GN630V tool's interface, so the AlphaWRT UI works unchanged.
- `image/en7528.mk`: `Device/fiberhome_sr1041y` (`tclinux-ubi`,
  `tclinux-free-bootbase-jump`, `TRX_LOADADDR` 0x80002000, 40 MiB banks).
- `base-files/lib/functions/econet.sh`: `get_mac_sr1041y` (parses `factory_conf`).
- `base-files/lib/preinit/09_mount_factory_data`: mounts the `factory` volume
  of the `config` UBI device.
- `en7528/base-files/lib/preinit/79_sr1041y_factory`: copies the EEPROM to
  `/lib/firmware/mediatek/mt7915_eeprom_sr1041y.bin` (`initramfs` and
  `preinit_mount_root` hooks).
- `en7528/base-files/etc/board.d/02_network`: WAN = `lan1` (port 1), LAN =
  `lan2..lan4`; LAN MAC = `brmac`, WAN MAC = `internetmac` (`brmac + 1`), label
  MAC = `brmac - 1`.
- `en7528/base-files/etc/uci-defaults/05_alphawrt_board`: `alphawrt.board.fibre=0`
  and `wan_port=lan1`, so AlphaWRT's pages offer router mode only (below).
- `base-files/etc/hotplug.d/ieee80211/10_fix_wifi_mac`: Wi-Fi MACs `brmac + 2`,
  `brmac + 3` (stock `APMAC_*` are placeholders).
- `config/sr1041y.config`: `gn630v.config` with the target switched and
  `prometheus-node-exporter-lua*` dropped (see build notes).

## Router mode only

The board has no fibre, so `05_alphawrt_board` sets `alphawrt.board.fibre=0`
and AlphaWRT's pages follow it: Quick Setup skips the mode, fibre identity and
"plug in the fibre" steps and puts the Internet on the WAN port (port 1, shown
as "WAN"); the Fibre page, the Fibre card on Home and the PON card on LuCI's
Status > Overview are hidden. Boards without that option (the GN630V) are
unchanged.

### Fixes to the EN7528 tree (affect other boards too)

1. **No DTB on `tclinux-ubi` initramfs images.** `en7528/config-6.18` sets
   `CONFIG_MIPS_ELF_APPENDED_DTB`, but `Device/tclinux-ubi` builds the
   initramfs as `kernel-bin | append-dtb`, which appends a raw DTB. The kernel
   panics with `no dtb found`. Switching to `CONFIG_MIPS_RAW_APPENDED_DTB`, as
   OpenWrt's econet target uses, fixes it; FIT/U-Boot boards (XC220-G3V) are
   unaffected because the bootloader passes the DTB.
2. **Console turns to garbage/NULs at handover.**
   `patches-6.18/886-uart-add-en7523-support.patch` calls
   `en7523_set_uart_baud_rate()` *before* `serial8250_set_divisor()`, which
   then overwrites BRD. New `888-serial-8250-airoha-program-XYD-after-the-divisor.patch`
   restores the mainline order (after the divisor, inside the port lock).
   Generated by `mk_uart_patch.sh`.
3. **UART clock.** The free bootbase leaves XYD set up for a 7.3728 MHz base
   clock, not the 1.8432 MHz the dtsi assumes for U-Boot boards. Overridden in
   the SR1041Y DTS only.
4. **MT7915 HIF2 resets the SoC.** With both PCIe links enabled, `mt7915e`
   resets the EN7528 as soon as it binds through the second host interface.
   On the main link alone both bands work. Left disabled; root cause open.

### Build notes (AlphaWRT `build.sh`)

- **Linux arm64 hosts:** `golang-bootstrap` cannot build there (`go-bootstrap
  cannot be installed on linux/arm64`). Use the distribution's Go, as
  `build.sh` already does for macOS:
  `CONFIG_GOLANG_EXTERNAL_BOOTSTRAP_ROOT="$(go env GOROOT)"` and
  `# CONFIG_GOLANG_BUILD_BOOTSTRAP is not set`. Building `golang1.27` under
  `-j9` in an 8 GB VM failed once and passed on its own; likely memory.
- **MIPS:** `prometheus-node-exporter-lua` pulls `modemmanager` as a source
  build dependency, which pulls `glib2`, whose bundled libffi fails to
  assemble its MIPS code. Dropped for SR1041Y; `alphawrt-homelab` already
  copes with the exporter being absent.
- `tools/budget.py` and `build.sh` assume `en7523`/`gn630v`; they need a
  device parameter.

## RAM boot

Needs the UART. Takes about 27 minutes at 115200 for a 15.5 MiB image.

```sh
python3 -I tools/ram_boot.py openwrt/bin/targets/airoha/en7528/*fiberhome_sr1041y-initramfs-kernel.bin
# then power-cycle the board
```

`ram_boot.py` catches "Press any key in 3 secs to enter boot command mode",
runs `xmdm 80020000 <len>` (bootbase arguments are **bare hex**: a `0x`
prefix parses as 0 and crashes the bootbase), sends the image with XMODEM-CRC
in 128-byte blocks, then `jump 80020000` (`CONFIG_ZBOOT_LOAD_ADDRESS`). The
bootbase can drop characters right after a transfer, so the jump is typed
slowly and its echo checked. A power cycle returns to the stock firmware.

Other tools: `enter_bootmode.py` (stop at `bldr>`), `listen.py` (passive
console), `loopback.py` (adapter self-test), `wifi_test.py` (load `mt7915e`
with full console capture, optionally without HIF2), `install_bank_b.sh`,
`set_bank.sh` and `mkflag.py` (see Install).

## Install

AlphaWRT goes into bank B; bank A keeps the stock firmware. The free bootbase
picks the bank from a flag record in bank A's UBI and falls back to the other
bank if the chosen kernel's CRC is wrong ([BANK-FORMAT.md](BANK-FORMAT.md)).

**First install** (needs the UART once):

1. Back up the whole flash first (the factory data is unique to the unit).
2. RAM-boot the initramfs image (above).
3. From the Mac, check the kernel and make the flag records:
   ```sh
   python3 tools/mkflag.py check kernel.trx        # the device's -kernel.bin
   python3 tools/mkflag.py flags .                 # flag-bankA.bin, flag-bankB.bin
   ```
4. Copy `kernel.trx`, `root.squashfs`, `flag-bankB.bin` and
   `tools/install_bank_b.sh` to `/tmp` on the board and run:
   ```sh
   sh /tmp/install_bank_b.sh /tmp/kernel.trx /tmp/root.squashfs /tmp/flag-bankB.bin
   reboot
   ```
   The script formats bank B, writes the kernel to UBI volume 0 and the rootfs,
   reads both back, then writes the bank-B flag record.

**Upgrades:** `sysupgrade` with the `*-squashfs-sysupgrade.bin`, over LAN, as
on any OpenWrt device.

**Back to stock:** `alphawrt-bootbank stock` (or System → Firmware banks),
then reboot. Without a working AlphaWRT, RAM-boot it and run
`tools/set_bank.sh flag-bankA.bin`.
